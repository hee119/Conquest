# 3. 구조체 캐릭터로 모의 전투하기 — O(1) 계산

## 원리와 전투 규칙

`Character` 구조체에 이름, 체력, 방어율(%), 공격력, 초당 공격 횟수를 묶어 저장한다. 상태 이상이나 회복 없이 서로 일정한 속도로 공격한다.

```text
1회 피해량 = 공격자의 공격력 × (1 - 상대 방어율 / 100)
공격 간격 = 1 / 공격 속도
처치에 필요한 공격 횟수 = 올림(상대 체력 / 1회 피해량)
상대를 처치하는 시각 = 필요한 공격 횟수 / 공격 속도
```

예를 들어 공격력 25, 상대 방어율 10%라면 한 번에 22.5의 피해를 준다. 공격 속도가 2/s이면 0.5, 1.0, 1.5초처럼 공격한다. **첫 공격은 0초가 아니다.**

이 문제의 전투는 피해량과 속도가 일정하므로 모든 공격을 반복할 필요 없이 처치 시점을 계산할 수 있다. 서로 다른 속도와 동시 공격을 반영하며, DPS만 비교하는 방식과도 다르다. DPS만 비교하면 마지막 타격의 시점과 올림 처리를 놓칠 수 있다.

## 코드의 기능

1. `Main`에서 A와 B를 `new Character(...)`로 선언한다.
2. `IsValid`로 능력치 범위를 검사한다.
3. `Simulate`에서 상대에게 주는 피해량과 공격 가능 여부를 구한다.
4. 양쪽 모두 피해를 줄 수 없으면 무승부다. 한쪽만 피해를 줄 수 있으면 그쪽이 승리한다.
5. 둘 다 공격 가능하면 직접 만든 `CeilingPositive`로 필요한 타격 수를 올림한다. 정수 변환으로 소수부를 버리고 원래 값과 비교해 올림 여부를 정한다.
6. 처치 시각을 비교해 빠른 쪽을 승자로 판정한다. 같은 시각이면 서로 마지막 타격을 주므로 동시 사망이다.
7. 승리 시점까지 패자가 공격한 횟수도 구해 승자의 남은 체력을 출력한다.

나눗셈으로 만든 소수 시각을 비교하는 대신 교차 곱을 비교한다. `aHits / aSpeed`와 `bHits / bSpeed`의 비교는 `aHits × bSpeed`와 `bHits × aSpeed`의 비교로 바꿀 수 있다. 공격 속도가 0인 경우는 먼저 따로 처리한다.

`decimal`은 0.1, 22.5 같은 십진 능력치를 표현하기 위해 사용한다. 숫자 뒤의 `m`은 decimal 리터럴이라는 표시다. 계산 범위와 정밀도를 관리하도록 체력/공격력은 최대 1,000,000, 공격 속도는 최대 1,000이며, 능력치는 소수 둘째 자리까지 허용한다. 방어율은 0~100%다.

`Math.Ceiling`, `Math.Floor`, `Math.Max`, `decimal.Truncate`는 사용하지 않는다. 올림·내림은 직접 만든 메서드로 처리하고, 체력 하한과 소수 자릿수 검사는 비교와 나머지 연산으로 처리한다.

## 기본 예시의 결과

| 캐릭터 | 체력 | 방어율 | 공격력 | 공격 속도 |
| --- | ---: | ---: | ---: | ---: |
| A | 100 | 20% | 25 | 2/s |
| B | 120 | 10% | 30 | 1/s |

- A는 B에게 22.5씩 피해를 주므로 6회, 즉 3초에 B를 쓰러뜨린다.
- B는 A에게 24씩 피해를 주며 1, 2, 3초에 총 3번 공격한다.
- 같은 3초의 B 공격도 적용하므로 A의 남은 체력은 `100 - 24 × 3 = 28`이다.

```text
3초: A 승리
A 체력: 28, B 체력: 0
```

## 다른 결과 시험하기

`Main`의 두 선언만 바꾸면 된다.

```csharp
// 둘 다 2초에 상대를 처치하므로 동시 사망.
Character a = new Character("A", 100m, 0m, 50m, 1m);
Character b = new Character("B", 100m, 0m, 50m, 1m);

// 둘 다 피해를 줄 수 없어 무승부. 위 선언 대신 사용한다.
Character a = new Character("A", 100m, 100m, 50m, 1m);
Character b = new Character("B", 100m, 100m, 50m, 1m);
```

구조체는 값 형식이므로 `Simulate(a, b)`에 전달한 상태는 복사본이다. 이 예제는 결과를 출력하고 종료하므로 호출자에게 수정된 캐릭터를 반환하지 않는다. 계산 시간과 추가 공간은 O(1)이다.

## 최적화 검토

기존 코드가 이미 공격 반복을 없앤 O(1) 계산이므로 이 원리를 유지했다. 능력치를 구조체에 저장하고, 처치 시각을 직접 구하며, 교차 곱으로 동시 사망도 판정한다. 공격력이나 체력에 따라 반복 횟수가 늘어나는 코드로 바꾸지 않았다.
