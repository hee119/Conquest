# 5. 성냥개비로 만드는 최대 정삼각형 개수 — 최적화판

## 적용한 규칙

사용자가 확인한 대로 **변을 공유할 수 있으며, 크기가 다른 큰 삼각형도 모두 센다.** 9개로 한 변이 성냥 2개인 삼각 격자를 만들면 작은 삼각형 4개와 큰 삼각형 1개, 총 5개다.

추가로 일반적인 성냥 배치 문제의 조건을 사용한다.

- 성냥은 모두 같은 길이이며 자르거나 구부리지 않는다.
- 성냥은 끝점끼리 연결한다. 서로 교차하거나 같은 위치에 포개지 않는다.
- 삼각형의 각 변은 성냥을 일직선으로 이어 붙여 만든다.
- 성냥은 일부 남겨도 된다. 남는 성냥을 삼각형과 떨어진 곳에 두어도 개수는 같으므로, 전부 사용하되 남는 성냥을 별도로 두는 해석에도 대응한다.
- 탐색하는 배치는 표준 삼각 격자 위의 배치다. 임의의 교차점이나 성냥 중간 접촉을 허용하는 문제라면 이 코드의 대상이 아니다.

## 단순 공식이 맞지 않는 이유

`N / 3`은 성냥을 공유하지 않는 작은 삼각형만 만드는 경우다. 공유를 허용하면 5개로도 삼각형 2개를 만들 수 있다. `(N - 1) / 2`는 삼각형을 한 줄로 계속 붙이는 배치에서는 쓸 수 있지만, 모든 배치의 최댓값은 아니다. 9개에서 작은 삼각형만 세면 4개지만 큰 삼각형까지 세면 5개다.

또한 한 가지 큰 삼각 격자 모양에 대한 개수 공식만으로는 다른 형태의 배치를 비교할 수 없다. 이 코드는 가능한 배치를 탐색한 뒤 각각의 삼각형 수를 직접 센다.

## 풀이 원리: 백트래킹

1. 한 개의 정삼각형으로 시작한다. 시작 삼각형의 크기도 여러 가지를 고려한다.
2. 기존 배치의 성냥 끝점에 맞닿는 새로운 삼각형을 붙여 본다.
3. 새로 필요한 성냥 수가 예산을 넘으면 그 후보를 버린다.
4. 완성된 모든 크기의 삼각형을 세고 최댓값을 갱신한다.
5. 재귀 호출로 더 붙여 본 뒤, 추가한 성냥을 제거해 다른 후보를 시험한다.

삼각형에 속하지 않는 성냥은 개수를 늘리지 않는다. 떨어진 배치도 삼각형을 손상시키지 않고 끝점끼리 맞닿게 옮길 수 있으므로, 삼각형들이 끝점으로 이어진 배치를 탐색한다. 새 삼각형은 기존 성냥을 공유해도 되며, 실제로 추가되는 성냥만 예산에서 계산한다.

서로 다른 크기나 뒤집힌 방향을 빠뜨리지 않도록 위/아래 방향과 한 변 길이 1부터 `N / 3`까지를 모두 검사한다. 삼각형의 꼭짓점뿐 아니라 둘레의 성냥 연결점도 접점으로 사용한다.

## 최적화한 부분

정답 조건과 탐색하는 배치는 유지하고, 탐색 단계마다 생기던 중복 계산과 할당을 줄였다.

1. **삼각형 모양 재사용**: 크기·방향별 성냥과 둘레 끝점을 `BuildTemplates`에서 한 번만 만든다. 이후에는 시작 좌표만 옮겨 사용한다.
2. **후보를 값으로 비교**: 성냥 목록을 문자열로 변환하는 대신 시작 좌표와 모양 번호를 가진 `Candidate` 구조체를 `HashSet`에 넣는다.
3. **예산 초과 즉시 중단**: 새 성냥이 남은 예산보다 많아지는 순간 그 후보의 나머지 성냥은 검사하지 않는다.
4. **추가 성냥 배열 재사용**: 재귀 호출 단계마다 `Edge[]` 하나를 만들고, 그 단계의 모든 후보에서 재사용한다. 후보마다 새 목록을 만들지 않는다.
5. **삼각형 개수 검사 시 목록 생성 제거**: 수평 밑변이 있는 크기까지만 검사하고, 나머지 두 변은 `HasLine`으로 직접 조회한다.
6. **배치 키 생성 비용 감소**: 12개 회전·대칭마다 문자열을 만들지 않는다. 배열 두 개를 재사용해 대표 배치 하나를 정한 후 키 문자열을 한 번만 만든다.
7. **직접 구현한 힙 정렬**: `Array.Sort` 대신 `Edge.CompareTo`를 이용하는 힙 정렬을 사용한다. 배열을 추가로 만들지 않고 O(n log n) 시간에 정렬한다.
8. **좌표 숫자 변환 제거**: 배치 키에 좌표 비트를 직접 저장한다. 내부 키이므로 화면에는 출력하지 않는다. 정확한 좌표 전체를 저장하므로 해시값만 비교하는 근사 판정이 아니다.

## 코드의 기능

| 기능 | 역할 |
| --- | --- |
| `Point` / `Edge` | 삼각 격자 좌표와 성냥을 값 형식으로 표현한다. |
| `Template` / `BuildTemplates` | 크기·방향별 삼각형 모양을 사전 계산한다. |
| `Candidate` | 새 삼각형의 위치와 모양 번호를 저장한다. |
| `HashSet<Edge>` | 현재 배치의 성냥을 중복 없이 저장한다. |
| `Search` | 후보 생성 → 예산 검사 → 추가 → 재귀 탐색 → 제거를 수행한다. |
| `CountTriangles` / `HasLine` | 밑변과 두 측면이 완성된 모든 크기의 삼각형을 센다. |
| `MakeTriangle` / `AddSide` | 사전 계산용 삼각형 성냥 목록을 만든다. |
| `GetVertices` | 배치의 끝점을 중복 없이 모은다. |
| `Move` / `Transform` | 성냥 이동과 60도 회전·대칭을 처리한다. |
| `GetCanonicalKey` / `CompareLayouts` | 이동·회전·대칭으로 같은 배치를 같은 대표 배치로 만든다. |
| `Encode` / `WriteCoordinate` | 대표 배치의 정확한 좌표를 내부 키 문자열로 저장한다. |

`IEquatable`, `GetHashCode`, `IComparable`, `List`, `HashSet`은 기본 .NET 기능이다. 좌표 최솟값 비교, 배열 복사, 정렬은 반복문과 비교 연산으로 직접 처리한다. 외부 라이브러리나 Unity API는 쓰지 않는다.

## 실행 예시

| 성냥 수 | 최대 개수 |
| ---: | ---: |
| 0, 1, 2 | 0 |
| 3, 4 | 1 |
| 5, 6 | 2 |
| 7, 8 | 3 |
| 9 | 5 |

```text
입력: 9
출력: 최대 정삼각형 개수: 5
```

## 성능

이 문제는 앞의 네 문제보다 훨씬 어렵다. 배치 수가 성냥 수에 따라 급격히 증가하므로 작은 입력부터 실행해야 한다. 큰 입력에서는 계산 시간이 길어지고 메모리도 많이 사용한다. `Ctrl+C`로 실행을 중단할 수 있다. 이 코드는 작은 입력에 대한 완전 탐색 학습용이며, 수백·수천 개를 빠르게 계산하는 프로그램은 아니다.

## 기존 버전과 속도 비교

같은 컴퓨터에서 Mono로 각 버전을 별도 실행한 1회 측정값이다. 프로그램 시작 시간도 포함한다. .NET 버전, 컴퓨터 상태, 입력에 따라 달라질 수 있다.

| 성냥 수 | 기존 | 최적화판 | 결과 |
| ---: | ---: | ---: | ---: |
| 12 | 약 0.894초 | 약 0.300초 | 둘 다 6개 |
| 15 | 약 24.808초 | 약 2.000초 | 둘 다 9개 |

15개에서는 이 측정 기준 약 12.4배 빨라졌다. 완전 탐색의 배치 수 자체를 없앤 것은 아니므로 큰 입력에 대한 시간·메모리 한계는 여전히 있다.
